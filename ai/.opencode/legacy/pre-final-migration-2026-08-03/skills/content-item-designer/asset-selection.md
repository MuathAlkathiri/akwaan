# Asset Selection

## Purpose

Experience & Recognition Questions begin with memorable Assets. Never search
only for a generic image when a meaningful moment is available.

Wrong: `image of Kakashi`

Better: `Kakashi revealing his Sharingan during the Zabuza fight`

## Selection Rules

A good Asset is recognizable, readable, focused on one memorable moment, fair
for the intended audience accessibility, and suitable for a supported Content Pattern.
Media must pass the removal test in the Design Bible.

Describe the intended moment precisely. Choose the source most likely to trigger
recognition without exposing the answer. Avoid posters, promotional renders,
wallpapers, visible answer text, and player-visible filenames that reveal the
answer. Hard Media may be less prominent, but must not be blurry, misleading,
or artificially obscured.

## Asset Task

For each Media candidate record:

- intended Content Pattern and required observation;
- source and attribution when available;
- Media type, supported format, safe filename, and relative destination;
- checks required before the candidate can be approved.

A remote URL is a source, not a completed Asset.

`generated_image` is reserved as a provider-neutral future task type. It remains
incomplete until an actual supported local file exists. This Skill selects no
provider and implements no image generation.

## Reuse

One Asset may support different questions only when each has a different tested
observation or memory. Rewording the same event and answer is duplication.
